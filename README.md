# 스킬 규칙

스킬은 한 가지 작업을 반복할 수 있게 적어 둔 폴더다. 진입점은 `SKILL.md`이고, 에이전트는 이름과 설명만 먼저 본 뒤 필요할 때 본문을 읽는다.

## 폴더

```text
skill-name/
├── SKILL.md          # 필수. 이름, 설명, 절차
├── scripts/          # 선택. 같은 코드를 반복해서 쓸 때
├── references/       # 선택. 특정 경우에만 읽는 문서
└── assets/           # 선택. 결과물에 넣는 템플릿·파일
```

폴더 이름은 `name`과 같다. 소문자, 숫자, 하이픈만 쓰고 64자 이하다. 비어 있는 하위 폴더는 만들지 않는다. 새 스킬은 `skill-template.md`를 복사해 시작한다.

## SKILL.md

앞부분은 이 두 칸만 필수다.

```yaml
---
name: skill-name
description: 무엇을 하는지, 어떤 요청일 때 쓰는지. 한두 문장.
---
```

`description`은 1024자 이내다. 하는 일과 발동 조건을 같이 적는다. 절차, 예시, 도구 목록은 넣지 않는다. 비슷한 스킬과 겹치면 쓰지 않는 경우만 한 구절로 적는다.

본문 순서는 아래를 따른다.

1. 소개. 목적 두세 문장.
2. 절차. 실제로 따르는 순서.
3. 산출물. 형식이 정해져 있을 때만.
4. 예. 판단이 갈리는 경우 하나.

언제 쓰는지는 본문에 다시 풀어 쓰지 않는다. 말투는 명령형으로 쓴다. 모델이 원래 하는 일, 장식 문장, 쓰지 않는 예외는 뺀다.

## 길이

| 부분 | 길이 |
|---|---|
| description | 1–3문장 |
| 본문 | 보통 80–200줄 |
| 본문 상한 | 500줄 |
| references 한 파일 | 한 주제. 길면 목차를 둔다 |

500줄에 가까우면 절차는 `SKILL.md`에 두고, 스키마·사례·세부 절차는 `references/`로 옮긴다. 본문에서는 그 파일을 언제 읽을지만 적는다.
